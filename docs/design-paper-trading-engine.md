## Problem Statement
Sahil (India) wants to learn how a real arbitrage bot behaves, with a live P&L ticker as the payoff, without risking money. A read-only spread logger (`arb_logger`: `logger.py`, `analyze.py`, `arb/costs.py`, `arb/venues.py`, `arb/store.py`) exists and was probed live on 8 of 9 exchanges (OKX unreachable from this machine; ZebPay USDT books empty, INR books fine). It prices every route after fees, 18% GST, the USDT/INR leg, transfers, 31.2% tax and 1% TDS (reported as locked cash). First live smoke test (55 cycles, ~8h wall-clock with gaps): zero routes profitable after costs; average gross 2.8 bps vs ~77 bps costs. So the engine is a learning tool, not a profit bet. The PRD/BRD gate any bot behind 7 days of live logging; for a learning goal those gates are loosened (see Premises).

## What Makes This Cool
A live P&L ticker: simulated trades fire as gaps open, with running INR profit after every cost and TDS-locked cash shown separately. Expect mostly red; watching where the money leaks is the lesson.

## Constraints
- No real money, no trade keys, no order API.
- Indian costs: 1% TDS per transfer (including buying a coin with USDT), 30% + 4% cess with no loss set-off, 18% GST on fees, INR cannot go offshore (USDT leg needed).
- BRD/PRD rules the engine honors: max 30% of capital on one exchange (BR-5); auto-stop on loss limit, stale feed or outage (BR-6); small coin inventory (BR-7); full trade record (BR-9).
- Fee, withdrawal and confirmation defaults in `config.yaml` are unverified (`VERIFY`).
- Stored data limit: `arb/store.py` keeps only top-of-book plus precomputed VWAP at three fixed sizes (₹50k, ₹2L, ₹5L). It does not store full books.

## Premises
1. The engine is worth building even if live logging shows no net-positive route. A red ticker is a result for a learning project. (Loosens the PRD kill criteria.)
2. It reuses `arb/costs.py` (`CostModel.evaluate`, a stateless pricing function) and the venue adapters. The ledger and TDS tracking are new code; costs.py is not forked.
3. It simulates the pre-funded model: cash on both exchanges, both legs fire together, periodic rebalance.
4. Fill independence holds only for the live feed (walk the full book at the next poll plus seeded random latency). Replay is NOT independent: it uses the next snapshot's stored VWAP at the nearest logged size (₹50k/2L/5L) plus seeded slippage, i.e. the logger's own data with noise; trade sizes are restricted to those three. Agreement with `analyze.py` is a sanity check, not validation. To make later replay real, the logger gains a `--full-books` option that stores the top ~25 levels per side per poll (decided at CEO review; paper P&L is an upper bound either way: no queue position, no adverse selection).
5. A ticker that never trades teaches nothing. With costs ~28x the edge in the smoke test (gross 2.8 bps vs ~77 bps costs, 55 cycles over ~8h with gaps), `min_net_bps=5` will rarely fire. The engine therefore has a **what-if mode**: scale costs by a factor and/or toggle GST, TDS, tax, FX leg and transfers off, so trades fire and each cost's effect can be seen. Real-cost mode stays the default. Results from a few hours/days of one market regime are anecdotal.

## Engine Rules (fixes review gaps; all values are config defaults)
- **Decision rule:** take a route when net edge after all costs (via `evaluate`) is at least `min_net_bps` (default 5), sized at one of the logged sizes, with a per-route `cooldown_polls` (default 3).
- **Cost application per simulated trade:** taker fee on both legs when filled; GST 18% on fees; FX leg charged when the two venues quote different currencies; 1% TDS on each leg that is a VDA transfer, added to `tds_locked` (never released in-run, shown separately; "if recovered" shown as an alternative line); 31.2% tax charged on positive gross gain only, no loss set-off, fees not deductible.
- **Ledger:** per-exchange cash (INR, USDT) and coin balances; a trade is rejected if either leg lacks balance or would push one exchange above 30% of total capital.
- **Transfer cost, charge once:** `CostModel.evaluate` in prefunded mode already amortizes the transfer cost over `rebalance_every` trades (`move /= rebalance_every`). The ledger must either (a) use that amortized figure per trade and make rebalances free, or (b) call `evaluate` with `rebalance_every` set so `transfer` is zero for trades and charge the real cost only on actual rebalances. Default: (b), because it shows true rebalance timing. Never both.
- **What-if mode:** recompute `net` from the component dict `evaluate` returns (`fees, gst, fx_leg, transfer, tax, tds_locked`) with a per-component multiplier (0 = off). No change to `costs.py`.
- **Rebalance:** trigger when an exchange's cash or coin falls below `rebalance_low` (default 20% of its target). Cost = withdrawal fee + GST + TDS; transfer takes the confirmation time from config, during which that balance is unavailable and no trades use it.
- **Kill switch:** stale = no update for more than 3 polls (30s); outage = an exchange missing from 3 consecutive polls (its routes are disabled; all trading stops if fewer than 2 venues remain); daily loss limit = `daily_loss_limit_inr` (default ₹10,000, to be set by Sahil). Each is a test case in replay.
- **Edge cases:** thin book or partial fill = skip the trade (no partial trades in v1); one-leg-worse-after-lag is captured by pricing both legs at the next poll; feed gap in replay = treated as stale; restart = run starts from a saved ledger snapshot; timestamps are the logger's cycle timestamp, not per-exchange clocks.
- **Determinism:** random latency/slippage is seeded; the seed is stored in the run record, so same log + same seed = same ledger.

## Feed Interface
`next()` returns one poll: `{cycle, ts, usdtinr, quotes: [{exchange, quote, base, size_inr, bid, ask, vwap_buy, vwap_sell, full_buy, full_sell}], down_exchanges: [...]}` (the same shape as the SQLite rows), or `None` at end of data. Replay reads SQLite by cycle; live polls the adapters and writes the same rows, so every live run becomes replayable.

## Ticker (v1)
One line per poll, refreshed in place: `time | trades | gross ₹ | costs ₹ | net ₹ (after tax) | TDS locked ₹ | worst exchange % | state(RUN/STOPPED:reason)`, plus a second line with running totals per cost category (`fee | GST | FX | transfer | tax | TDS`), so "where the money leaks" is visible without a per-trade autopsy. When no trade has fired, show the best route's net bps ("closest to profitable"). Per-trade explanations and replay speed-ups are later.

## Approaches Considered
### Approach A: Replay-first engine (minimal)
Replay the logger's SQLite log with a simulated ledger and kill switch. Effort S. Low risk. Repeatable, not live.
### Approach B: Live paper engine (ideal)
Poll live books, decide, fill against next-poll books with jitter; ledger, cap, kill switch. Effort M-L. Medium risk; needs a stable host; hard to reproduce unless it records what it sees.
### Approach C: One engine, two feeds (chosen)
Engine against the feed interface above, with a SQLite replay source and a live source. Build replay first, then add live. Files: `engine/feed.py`, `engine/ledger.py`, `engine/fills.py`, `engine/killswitch.py`, `engine/run.py` (ticker + loop), `tests/test_engine.py`. Effort M, in two steps; line count is a floor (~900+) because ledger/TDS/rebalance is the hard part.

## Recommended Approach
Approach C. Replay gives a fast debug loop and is how the kill switch and ledger rules get tested without waiting for the right market; the live feed delivers the ticker.

## Success Criteria
- Same log + same seed produces the same ledger and P&L.
- Ledger never exceeds the 30% per-exchange cap; kill switch trips in test cases for stale feed, outage and loss limit.
- Coin inventory stays under a configured cap (BR-7), checked in a test.
- Live ticker updates every poll with TDS-locked cash shown separately.
- Paper P&L is comparable with `analyze.py`; disagreement is explained, not hidden.
- Every simulated trade stored with a cost breakdown (BR-9).

### Engine contract changes (all from the eng review, verified against code where noted)
1. **Transfer cost charged once.** Call `evaluate` and drop its `transfer` component from trade net (`net += ev["transfer"]`); only the ledger's Rebalancer charges transfers. No change to `costs.py`.
2. **Rebalance TDS is a config flag** `tds_on_rebalance` (default false, matching `costs.py` which charges no TDS on moves). Verified.
3. **Feed contract fixed.** Add a `cycle_status`/`down` record to `store.py` (additive) so outages are stored, not inferred. Quote `ts` is per-book fetch time; the engine clock is the cycle `ts`. Full books go in a separate `levels(cycle, exchange, quote, base, side, json)` table (one JSON blob per market per poll, not a row per level), with a size cap and max-days rotation. Verified: `store.py` has no down record.
4. **Pending-order queue.** Orders decided at poll t fill at poll t+1 and reserve balance meanwhile. Cancel if a leg's exchange is missing at t+1 or the `ts` gap exceeds 3 x poll interval.
5. **Engine = pure `step(state, snapshot) -> (state, events)`.** Ticker, replay, live and the restart snapshot all consume the same state/events. Extra components: `pricing.py` (reuses `routes.py` conversion and `evaluate_cycle`), `guard.py`, `persist.py`, `config` what-if transform.
6. **Single SQLite writer.** The live feed reuses the logger's loop; the engine subscribes. No second writer on one DB.
7. **Guard (new, before decisions).** Reject quotes that are NaN/inf, price <= 0, or more than 3% from the cross-venue median; skip cross-currency routes on `fx_source == "fallback"`; flag gross above `max_gross_bps` (300) as "suspect", never trade it.
8. **Determinism by key.** Each random draw uses `Random(sha256(f"{seed}|{cycle}|{route}|{size}"))`; sorted iteration with explicit tie-break `(net desc, route key)`; feed SELECT ordered by `cycle, rowid`. Must hold under different `PYTHONHASHSEED` and after a restart.
9. **Kill switch lifecycle.** STOPPED is sticky and persisted; reset is manual. "Daily" = IST date from log `ts`. Loss measured on realised spread net (after fees and tax), not MTM. A replay gap cancels pending orders and does not trip the switch.
10. **Snapshot** = balances, in-flight rebalances with ETA, pending orders, cooldown counters, open episodes, last cycle id, config hash, kill-switch state, day P&L. JSON only, atomic write (temp + `os.replace`), written after each full poll; resume asserts `next cycle == last + 1`.
11. **Sizing and cap.** Try sizes largest-first and take the first that passes the 30% cap and balance checks (so the 5L size is rejected under a 3L per-exchange cap). Cap rule: a trade may not push an exchange over 30% or add to an exchange already over it; MTM drift can still breach.
12. **Counting mode** is configurable: `episode` (matches `analyze.py`) or `cooldown`; the run record states which.
13. **P&L definition.** Ticker "net" = sum of spread-trade nets (after fees, GST, FX, tax). Inventory MTM drift on a separate line. Tax is the spread-gain approximation from `evaluate`, NOT lot-based capital gains; labelled as such. TDS is a non-spendable `tds_locked` bucket shown "if recovered at 100%"; no financial-year logic in v1.
14. **Rebalancing planner (v1):** one transfer per asset per ETA; INR -> USDT refills go through the FX leg (fee + spread + TDS) then USDT withdrawal; rebalance costs get their own ticker bucket. Config gains an `allocation:` target per exchange and asset.
15. **What-if mode** builds a modified copy of the config and a new `CostModel` (per-component multiplier, 0 = off) rather than scaling after the fact; the per-exchange `tds` flag is bypassed by `tds_rate = 0`. Factor 1 with no toggles must equal the baseline exactly.
16. **Shared helpers.** One `reference_mid` function (median); fix the `analyze.py` copy that picks `sorted(v)[len(v)//2]`, which differs for an even count (separate commit).
17. **"Closest to profitable" line** calls `evaluate` on all pairs (the existing route list only contains pairs with sell > buy).
